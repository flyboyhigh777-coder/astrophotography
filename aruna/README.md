# Аруна

Джйотиш-платформа: сидерическая карта рождения, небо дня, совместимость пары,
подбор времени и наставник, который читает карту, — с бесплатной базой и платными
разборами.

Три части, работающие независимо:

- **сайт** — статика без сборки: HTML, CSS и обычные `<script>`, расчёты идут
  в браузере, данные о рождении никуда не уходят;
- **телеграм-бот** — утренняя сводка, день, даша, мухурта, дневник состояния;
- **сервер и API** — проверяет оплату и отдаёт платные разборы, вход через бота.

Ни одной внешней зависимости нигде: ни npm-пакетов, ни сборки. Нужен только
Node 20+. Пошаговая инструкция для тех, кто раньше не поднимал серверов, —
[docs/SETUP.md](docs/SETUP.md).

## Быстрый старт

```bash
node server/api.js                      # сайт и API на http://127.0.0.1:8080
ARUNA_BOT_TOKEN=<токен> node server/index.js   # плюс телеграм-бот
npm install                             # только для разговора с Дипой
```

`index.html` открывается и двойным щелчком (`file://`) — модулей и `fetch` нет,
работает всё, кроме платных разборов и входа.

Единственная зависимость (`@anthropic-ai/sdk`) нужна только Дипе и стоит в
`optionalDependencies`: без `npm install` сайт, бот и сервер работают, а диалог
отвечает по правилам и говорит об этом прямо.

## Телеграм-бот

Сайт открывают раз в месяц, бота читают каждый день — поэтому бот здесь не
довесок, а главный инструмент удержания.

| Команда | Что делает |
|---|---|
| `/today` | панчанга, Луна по вашей карте, мухурта, стих |
| `/chart` | карта рождения: лагна, грахи по бхавам, йоги |
| `/dasha` | периоды Вимшоттари с датами |
| `/muhurta` | лучшее и худшее время сегодня, с выбором задачи |
| `/navamsha` | навамша D9 и варготтама |
| `/sav` | сарвашта-кавварга: бинду по раши, транзиты Шани и Гуру |
| `/mood` | отметить день одной кнопкой |
| `/stats` | на какие бхавы Луны падают ваши тяжёлые дни |
| `/digest` | утренняя сводка в 7 утра по своему часовому поясу |
| `/login` | подтвердить вход на сайте по коду |

Бот сам сообщает о смене антардаши и о входе Гуру или Шани в новый раши —
считает это заранее и пишет в день перехода.

**Дневник состояния** — статистика по собственным данным человека, а не
предсказание: он отмечает день кнопкой, а через три недели видит, на какие
бхавы Луны приходятся его тяжёлые дни. Если разброс мал, бот так и говорит.

## Сервер и оплата

`server/api.js` раздаёт сайт и держит API. Он же закрывает главную дыру
витрины: **полные разборы считаются на сервере и отдаются только после
проверки покупки** — без оплаты приходит 402.

Вход — через бота, без почты и паролей: сайт показывает код, человек шлёт
его боту командой `/login`, сервер связывает их и выдаёт токен.

```
POST /api/auth/start     код для входа
GET  /api/auth/poll      ждём подтверждения от бота
GET  /api/wallet         баланс, подписка, открытые разборы
POST /api/purchase       пополнение (в демо-режиме — бесплатно)
POST /api/unlock         купить разбор
POST /api/report         получить разбор (402, если не оплачен)
```

Приём денег пока не подключён: `DEMO = true` в `assets/js/core/access.js`.
Что сделать для настоящей оплаты — в [docs/SETUP.md](docs/SETUP.md), шаг 6.

## Деньги: где проходит граница

Не «три расчёта в день», а по природе работы:

- **бесплатно — всё, что считается:** карта целиком, навамша (D9), даша, панчанга,
  мухурта дня, транзиты, стих, сумма по 36 гунам, короткие ответы наставника,
  сохранение в PDF через печать браузера;
- **за биджи — всё, что разбирается:** йоги с правилами, сила грах, восемь варг
  с вимшопакой, полный парный отчёт, год вперёд по датам, подбор времени под
  задачу, подсказка по времени рождения, развёрнутый ответ наставника.

Приём оплаты **не подключён**. Модуль `assets/js/core/access.js` написан так,
чтобы это была одна точка замены — объект `ADAPTER` с методами
`load / save / buy / unlock`. Сейчас там localStorage и демонстрационный баланс
(6 бидж новому гостю), потом на его место встаёт HTTP-клиент, остальной код не
меняется.

> **Важно перед запуском оплаты.** Пока проверка доступа живёт в браузере, её
> можно обойти правкой страницы. Для витрины это нормально. Когда появятся
> деньги — полные тексты платных разборов должны приходить с сервера после
> проверки покупки, а не считаться на клиенте. Расчётное ядро переносится на
> Node как есть: оно не знает про DOM и уже работает под `node` в тестах.

## Западная натальная карта

Второй продукт на том же расчётном ядре — и сознательно другая астрология.
Джйотиш на этом сайте считает сидерический зодиак, западная карта —
тропический; разница около 24°, знак Солнца у большинства людей выходит разный,
и ни одна из систем при этом не ошибается.

Что считается:

- **Семь систем домов** — Плацидус, Кох, Региомонтан, Кампанус, Порфирий,
  равнодомная, целознаковая. Все семь **сверены со Swiss Ephemeris**, эталоном
  отрасли: максимальное расхождение 0,009 угловой минуты (полсекунды дуги) на
  2 688 сравнениях по восьми широтам от экватора до Мурманска.
- **Уран, Нептун, Плутон и средняя Лилит** — в джйотише их нет, западной карте
  без них нельзя. Точность против pyephem: Уран 115″, Нептун 73″, Плутон 67″ —
  то есть все три точнее Сатурна. Хирона нет намеренно: его орбита требует
  другого класса эфемериды, а правдоподобное число вместо точного — это не к нам.
- **Аспекты** с орбисами, зависящими от участников (светила слышно дальше),
  сходящиеся и расходящиеся, и конфигурации целиком: тау-квадрат с вершиной,
  большой тригон, йод, большой крест, стеллиум.
- **Эссенциальные достоинства** по классическим таблицам: обитель, экзальтация,
  тритоны по Доротею, термы египетские, деканы халдейские, изгнание и падение.
  Альмутен, перегрины, казими отдельно от сожжения. Дальние планеты в таблицу
  не попадают — таблицы старше их открытия, и называть Уран «перегрином» значило
  бы врать.
- **Рисунок карты** по Джонсу: пучок, чаша, корзина с ручкой, локомотив, качели,
  праща, всплеск. Одиночки по стихиям и крестам, финальный диспозитор.
- **Транзиты на год** — медленные планеты к точкам карты, с датами точных
  аспектов и всеми тремя проходами при ретроградности. Год считается за 65 мс.
- **Вторичные прогрессии** — сутки за год, с прогрессивными углами и фазой
  прогрессивной Луны.

**Колесо объёмное и живое.** Кольца разведены по глубине: подложка уходит
назад, планеты выступают вперёд, сетка аспектов лежит между ними. Это не
украшение — в плоском колесе сетка сливается с кольцами в клубок линий, а
разведённая по слоям читается сама собой. Объём делают CSS-перспектива и
шесть отдельных SVG, без единой библиотеки.

Что можно делать руками: повернуть и наклонить карту перетаскиванием,
навести на планету — остальное погаснет, останутся её аспекты и карточка с
разбором, навести на сектор — подсветится дом и его жильцы, щёлкнуть —
выбор закрепится. Аспекты фильтруются (все, только точные, только
напряжённые, никакие), транзиты сегодняшнего дня включаются вторым кольцом.
Всё то же делается с клавиатуры: планеты берутся табом, стрелки поворачивают
карту. Наклон всегда выключается одним щелчком, а на печать карта уходит
плоской: колесо — инструмент измерения углов, и перспектива их искажает.

**Толкования собираются из опорных слов по правилу, а не берутся готовыми.**
Готовых абзацев «Солнце в Овне» здесь нет: их пришлось бы или написать больше
тысячи, или у кого-то взять. Вместо этого у планеты есть своё дело и своя тень,
у знака — способ, у дома — область, у аспекта — условие; текст собирается из
них, и рядом показано правило, по которому он собран.

## День по знаку: считать, а не сочинять

Ежедневный гороскоп — самая лживая часть астрологии и самая
востребованная. Отказаться от него значит отдать людей тем, кто пишет
двенадцать абзацев наугад. Поэтому он здесь есть, но считается.

Правило называется **гочара** и описано в «Пхаладипике» Мантрешвары,
глава 26. Смотрят, в каком доме от вашего раши стоит сегодня каждая из
девяти грах; для каждой классика перечисляет дома, где её проход идёт
легко. Шани и Мангалу хорошо в третьем, шестом и одиннадцатом; Гуру —
во втором, пятом, седьмом, девятом и одиннадцатом; Шукре хорошо везде,
кроме шестого, седьмого и десятого. Одиннадцатый хорош всем.

Сверх таблицы посчитана **ведха** — то, что обычно выбрасывают.
Хороший проход перестаёт работать, если другая граха стоит в
определённом доме напротив: у Шани и Мангала третий гасится из
двенадцатого, шестой из девятого, одиннадцатый из пятого. Без этого
правила таблица обещает удачу там, где классика её уже отменила.
Две пары друг друга не гасят — Солнце с Шани и Луна с Будхой.

Третью пару пришлось добавить самим, и вот почему. Раху и Кету всегда
ровно в шести домах друг от друга — это геометрия, а не обстоятельство.
А ведха у обоих ставится как раз на шестой дом от каждого хорошего:
3→9, 6→12, 10→4, 11→5. Значит, ни один их хороший проход не сработал бы
никогда, и вся строка узлов была бы мёртвой. Ведха говорит о том, что
кто-то **мог** встать и загородить; там, где «мог» заменяется на
«всегда стоит», правило теряет смысл. Это единственное место, где мы
отошли от буквы источника, и сделано это осознанно.

Чего на странице нет:

- **Предсказаний событий.** «Вас ждёт встреча» нельзя ни посчитать, ни
  проверить. Дом от знака говорит, к чему день повёрнут.
- **Единой оценки дня.** Трудных домов у большинства грах больше, чем
  лёгких: у Шани их девять из двенадцати. Сложи такое в одно число — и
  выйдет, что у всех и всегда день плохой. Поэтому показан состав, а не
  балл.
- **Знака по Солнцу.** В джйотише дневные приметы читают от **Чандра-лагны**,
  знака Луны. Знак из журнальных гороскопов — солнечный и тропический,
  он обычно другой. Оба настоящие, но считаются от разного; на странице
  об этом сказано прямо, а знак Луны можно посчитать по дате рождения.

Стих подбирается тем же `pickVerse()`, что и в диалоге, но хозяин знака
передаётся парой `{tag, weight: 2}` вместо строки: он должен подкрашивать
выбор, а не править им, иначе за месяц человек увидит три текста.

### Хеш, из-за которого стих залипал

Стих выбирается как остаток от деления хеша даты на размер круга
подходящих. Хеш был FNV-1a — и этого оказалось мало: остаток берёт
младшие биты, а у FNV они почти не перемешиваются, потому что последнее
действие — умножение, и низ результата тянется из низа предыдущего шага.
На ключах вида «30 сентября 2026/Овен», где различие в конце строки,
круг из четырёх стихов выдавал один и тот же в семи случаях из десяти.

Лечится добивкой из murmur3 — два сдвига с XOR и два умножения после
основного цикла. Перекос упал с 70 % до 1,38 раза при худшем размере
круга, пустых корзин нет. Проверка стоит в `test/today.test.js`.

## Слова, которые никто не обязан знать

Джйотиш говорит на санскрите, западная астрология — на латыни. Заменить
эти слова русскими нельзя: они точные, и приблизительный перевод соврёт.
Поэтому слова остаются, а рядом появляется объяснение.

- `data/glossary.js` — шестьдесят с лишним терминов: как слово пишется,
  в каких формах его искать в тексте и что оно значит в одно-два
  предложения. Объяснение не должно объяснять термин термином.
- `ui/glossary.js` — размечает текст после отрисовки и показывает
  подсказку. Слово становится настоящей кнопкой: отзывается на мышь, на
  палец и на Tab, закрывается по Escape и не вылезает за край экрана.
- `glossary.html` — все слова разом, с поиском. Из подсказки туда ведёт
  ссылка на конкретное слово.

Три вещи, которые пришлось делать руками:

1. **Границы слова.** `\b` в JavaScript считает буквами только латиницу
   и с кириллицей молча не срабатывает. Заглядывание назад `(?<=…)`
   решило бы это, но его нет в Safari до 16.4 — а это половина айфонов
   на руках. Поэтому граница слева задана захватом символа, справа —
   просмотром вперёд.
2. **Наведение мышью не работает на телефоне.** Половина людей придёт с
   телефона, и «наведите на слово» для них пустой звук. Отсюда кнопка, а
   не `title`.
3. **Одно слово на панель.** Считать по абзацам — таблица из девяти строк
   со столбцом «Раши» получит девять подчёркиваний подряд. Считать по
   всей странице — объяснение окажется в шапке, а человек встретит слово
   в середине.

Рядом — `ui/howto.js`: полоска первых шагов там, где ещё ничего не
посчитано, и раскрывающееся «как читать» рядом с результатом. Второе
помнит, закрыли ли его: разобравшийся человек не должен закрывать одно и
то же при каждом заходе.

## Браузеры и телефоны

Проверяется не «в Хроме открылось», а три движка, потому что браузеров
много, а движков три:

| Движок | Какие браузеры |
|---|---|
| **Chromium** | Chrome, Яндекс.Браузер, Edge, Opera, Vivaldi |
| **WebKit** | Safari — **и на айфоне все остальные тоже**: Apple обязывает Chrome, Яндекс и Firefox использовать WebKit |
| **Firefox** | Firefox на компьютере и на Android |

`test/engines_check.mjs` прогоняет каждую страницу по всем трём на трёх
размерах экрана (телефон, планшет, компьютер) и ловит ошибки консоли,
незаполненные расчётные блоки и прокрутку вбок. `test/touch_check.mjs`
проверяет то, что видно только на телефоне: размер целей под палец и
шрифт в полях. `test/submit_check.mjs` жмёт сами кнопки расчёта — то,
чего не делал ни один из прогонов выше.

Что нашлось этими прогонами и починено — то, чего не видно в одном браузере:

- **Выпадающий список и галочки были белыми в Safari.** Вычисленные
  свойства при этом выглядели правильными: WebKit просто рисует свой
  элемент поверх, пока не сказано `appearance: none`. На айфоне список
  «Система домов» был нечитаем.
- **Поля меньше 16 пикселей.** iOS увеличивает всю страницу, едва
  коснёшься такого поля, и обратно она не возвращается.
- **Свёрнутое меню на телефоне занимало 29 пикселей** вместо нуля:
  `max-height: 0` не может пересилить отступы при `box-sizing:
  border-box`, и в этой полоске просвечивал верх первой ссылки.
- **Цели под палец.** 44 пикселя по рекомендации Apple и Google.
  Ссылки внутри абзаца из этого исключены намеренно: раздутая ссылка
  разрывает строку, и рекомендации её прямо исключают.
- **Общие правила лежали в `app.css`, а главная его не подключает** —
  у неё свой `landing.css`, и до неё правила не доходили. Всё общее
  переехало в `base.css`.

А это нашлось уже на живом телефоне — и объясняет, почему кнопка
«Построить карту» казалась мёртвой:

- **Подсказка про часовой пояс толкала кнопку вниз из-под пальца.**
  Пустая строка под полем города схлопывалась, а стоило городу найтись —
  разворачивалась на три строки и сдвигала кнопку на 59 пикселей ровно в
  тот момент, когда к ней тянулись. Нажатие приходилось на галочку
  «время неизвестно»: карта не строилась, а время молча заменялось на
  полдень. Теперь текст там есть всегда, а высота закреплена в стилях —
  проверено по всем 93 часовым зонам на шести ширинах экрана.
- **Обработчик формы западной карты читал не тот ответ.** `validate()`
  возвращает строку с ошибкой или `null`, а вызов ждал объект `{ok}` —
  и падал на `null`, то есть ровно при верно заполненной форме. Прежние
  браузерные прогоны жали «Показать на примере», а она считает напрямую:
  поломка прошла мимо всех 84 проверок.
- **Набранный город не засчитывался без тычка в подсказку.** На телефоне
  список закрывает клавиатура, и до него просто не добираются. Теперь имя
  принимается само, если совпало целиком или подошёл ровно один город.
- **Результат рождался ниже сгиба.** На узком экране форма и карта стоят
  друг под другом: расчёт проходил, но экран не двигался. `Aruna.reveal()`
  подводит страницу к результату — и только если его действительно не видно.
- **Страна вместо региона.** Ташкент подписывался «СНГ и Балтия»; теперь
  «Ташкент · Узбекистан», и список шире своего поля, иначе страна
  обрезалась. Заодно ушёл дубль «Тбилиси (Грузия)».

Сверх того сделано под телефоны: `viewport-fit=cover` и отступы от
выреза экрана, `dvh` вместо `vh` у меню и окон (иначе они уезжают под
адресную строку), выключена серая вспышка под пальцем, `overscroll-
behavior` у прокручиваемых панелей.

**Установка на домашний экран.** Есть `manifest.webmanifest`, иконки в
`assets/icons/` и теги Apple: сайт добавляется на экран телефона и
открывается без адресной строки, с быстрыми ссылками на натальную
карту, карту дня и диалог. Это не замена приложению, но пока его нет —
ближайшее к нему.

## Дипа: единственное место, где нужна языковая модель

Всё остальное в проекте считается кодом, и это не экономия, а принцип: числа не
требуют красноречия, а красноречие не считает числа. Разговор — исключение:
объяснить связь бхавы, хозяина и периода живыми словами правилами не выходит.

Устройство — в `server/lib/dipa.js`, и оно держится на четырёх решениях:

1. **Расчёт делает код.** `facts()` собирает карту, силы, йоги, периоды с датами,
   небо дня и бинду; `brief()` превращает это в плотный текстовый блок (~950
   токенов). Модель получает готовые факты и только истолковывает их.
2. **За фактом — в расчёт, а не в память.** Восемь инструментов
   (`graha_detail`, `bhava_detail`, `dasha_periods`, `transit_on`, `sav_table`,
   `varga_position`, `muhurta_today`, `find_verse`) дают модели тот же движок,
   которым считается сайт. Стихи цитируются только через `find_verse` — и чтобы
   перевод был наш, и чтобы не всплыл вспомненный.
3. **Голос описан запретами.** Блок `VOICE` перечисляет дословно то, чего
   говорить нельзя: «Конечно», «Важно отметить», «как языковая модель», а рядом
   «звёзды советуют», «энергетика», «проработать». Штампы узнаются мгновенно и
   обесценивают остальное, поэтому список запретов длиннее списка пожеланий.
   Задача — не выдать модель за человека (на странице честно сказано, что
   истолкование пишет модель), а чтобы ответ не был похож на ответ чат-бота.
4. **Всё проверяемо и всё работает без ключа.** Каждый ответ несёт след — какие
   обращения к расчёту за ним стоят; он показан под ответом. Нет ключа или нет
   пакета — отвечает разбор по правилам из `assets/js/jyotish/talk.js`.

Ключ: `server/config.json` → `{"anthropicKey": "sk-ant-..."}` или переменная
`ANTHROPIC_API_KEY`. Модель — `claude-opus-5-5`, меняется полем `dipaModel`.
`@anthropic-ai/sdk` стоит в `optionalDependencies`: без него работает всё, кроме
истолкования, и тесты это проверяют, пряча пакет.

Цена: короткий ответ бесплатен и без счёта, развёрнутый — 1 биджа **за каждый
раз** (единственное исключение из «открыл однажды — твоё навсегда»; почему
именно так, написано на странице тарифов). Суточные пределы стоят от
перерасхода, не от жадности.

## Что настоящее, а что нет

**Настоящее** — весь астрономический и джйотиш-расчёт: положения грах, лагна,
бхавы, накшатры с падами, панчанга, восход и закат, мухурта, Вимшоттари-даша,
Аштакута, йоги, сила грах, переходы медленных грах, саде-сати. Проверено
тестами и сверено с внешней эфемеридой.

**Настоящее** и диалог на `dialog.html`: спрашивать можно своими словами,
отвечает языковая модель, и она получает уже посчитанную карту — придумывать
положения ей запрещено, за фактом она обращается к тому же движку, что считает
сайт, и под ответом видно, к чему обращалась. Без ключа к модели диалог не
ломается: тогда отвечает разбор по правилам, и страница говорит об этом прямо.
Память беседы настоящая: переписка и заметка наставника — на сервере, у вошедших;
без входа — в `localStorage`.

**Заглушки** — разделы платформы (курсы, тренажёр памяти, древо рода, хинди,
школы): описаны на главной, страниц под ними пока нет.

## Метод расчёта

- Сидерический (нираяна) зодиак, аянамша **Лахири** (читрапакша).
- Бхавы — **целыми раши**: первая бхава равна всему раши лагны.
- Раху и Кету — **средние** узлы Луны.
- Положения видимые: с нутацией в долготе и годичной аберрацией.
- `TT` из `UT` через ΔT (полиномы Эспенака — Меуса).
- Часовой пояс места рождения берётся из базы IANA внутри браузера (ICU) — то
  есть с полной историей декретного и летнего времени. Москва 1975 → UTC+3,
  лето 1985 → UTC+4, 2012 → UTC+4 круглый год. Это одна из самых частых ошибок
  в самодельных калькуляторах карт.

### Точность

Сверка с `pyephem` (libastro: VSOP87 + ELP2000) на 1176 датах 1930–2050,
`test/validate_ephemeris.py`:

| Граха | Макс. ошибка | СКО |
|---|---|---|
| Луна | 14″ | 3,4″ |
| Солнце | 35″ | 12,3″ |
| Меркурий | 94″ | 21″ |
| Венера | 177″ | 25″ |
| Марс | 205″ | 35″ |
| Юпитер | 113″ | 31″ |
| Сатурн | 173″ | 58″ |

Пада накшатры для сравнения — 3°20′, то есть 12 000″.

Формула лагны сверена с прямым перебором по горизонту на семи местах от экватора
до 69° с. ш. — расхождение не больше 1,4″. Восход и закат совпадают с `pyephem`
с точностью до секунды. Длительность саде-сати, посчитанная независимо, выходит
7,4 года при классических 7,5 — это проверка сходимости всей цепочки.

### Что ещё считается

- **Аштака-варга и сарвашта-кавварга**: бинду по раши от восьми опор.
  Таблицы проверены контрольными суммами, которые классика задаёт независимо
  от карты: Сурья 48, Чандра 49, Мангала 39, Будха 54, Гуру 56, Шукра 52,
  Шани 39 — всего 337. Совпадение всех семи сумм практически исключает
  опечатку в таблицах.

- **Варги**: саптаварга (D1, D2, D3, D7, D9, D12, D30) плюс D10. Правила
  построения сверены с классическими эталонами в тестах. Остальные варги
  шодашаварги не включены: их правила в источниках расходятся сильнее.
- **Вимшопака-бала** по шадварге, веса 6/2/4/5/2/1 = 20. У Раху и Кету не
  считается: у них нет владений.
- **Ректификация** — перебор времени по минутам и проверка каждого варианта на
  согласие с событиями (даши и переходы Гуру и Шани по бхавам события). Сутки
  разбираются за ~50 мс. Это сужение круга, а не доказательство, и страница
  говорит об этом прямо.

### Где модель упрощена (и это написано на самих страницах)

- **Сила грах** — не классическая Шад-бала, а сводный индекс из пяти
  составляющих (достоинство, дигбала, движение, бхава, чистота от сожжения).
  Сравнивает грахи внутри одной карты, не между разными.
- **Вашья и йони** в Аштакуте — упрощённая симметричная матрица: источники
  расходятся в деталях. Остальные шесть кут — по общепринятым таблицам.
- **Ведха** в парных проверках сознательно не считается: опубликованные таблицы
  пар противоречат друг другу.
- **Сожжение (астангата)** — по умеренным общепринятым границам, без отдельных
  правил для ретроградных планет.
- Вимшоттари-год — 365,2425 суток.

## Тексты писаний

Стихи в `assets/js/data/verses.js` даны в транслитерации IAST, перевод —
**смысловой, сделанный для этого сайта**: это не перепечатка какого-либо
изданного перевода (почти все ходовые русские переводы Гиты под копирайтом).
Перед публикацией сверьте нумерацию и текст с печатным изданием.

Стих дня выбирается по правилу: хозяин вары, хозяин накшатры Луны и фаза Луны
собирают круг подходящих стихов, дата выбирает внутри него. Правило видно под
стихом.

## Тесты

```bash
./test/run_all.sh
```

- `unit.mjs` — 140 проверок расчётного слоя: инварианты, классические таблицы,
  доступ и списания. Работает на голом `node`.
- `bot.test.js` — 58 проверок: весь диалог бота от `/start` до утренней
  рассылки, без настоящего телеграма (подменяется единственный сетевой вызов).
  Отдельно — разговор с Дипой: списание за разбор, поведение на нуле, подписка.
- `api.test.js` — 44 проверки: вход через бота, кошелёк, покупки и главное —
  что неоплаченный разбор сервер не отдаёт.
- `dipa.test.js` — 104 проверки разговора: узнавание темы по словам, ответ по
  правилам, блок фактов для модели, все восемь инструментов (и их поведение на
  мусоре), разбор потока, возврат к правилам при сбое модели, `/api/talk` с
  оплатой за каждый раз, возврат денег при неудаче, память и «забыть».
  Настоящих запросов к модели нет: клиент подменяется заглушкой, тест идёт без
  сети и без денег. Без пакета `@anthropic-ai/sdk` группы, которые без него не
  проверить, честно пропускаются.
- `natal.test.js` — 93 проверки западной карты: инварианты домов во всех семи
  системах и на четырёх широтах, совпадение квадрантных систем на экваторе
  (это теорема, а не совпадение), отказ Плацидуса за полярным кругом,
  классические таблицы достоинств, конфигурации аспектов, транзиты и
  прогрессии, устойчивость к краям.
- `check_ascendant.mjs` — лагна против прямого перебора по горизонту.
- `validate_houses.py` — куспиды всех семи систем против **Swiss Ephemeris**
  (нужен `pip install pyswisseph`). 2 688 сравнений, порог — одна угловая минута,
  фактическое расхождение 0,009′.
- `validate_ephemeris.py` — сверка с `pyephem` (нужен `pip install ephem`).
- `browser_check.mjs` — все девять страниц в настоящем Chromium (30 сценариев,
  включая живое колесо: подсветка, закрепление выбора, фильтры, транзиты):
  ошибки консоли, заполнение расчётных блоков, отсутствие горизонтальной
  прокрутки, покупка разборов за биджи и открытие по подписке, вопрос Дипе
  своими словами и разворот ответа за биджу. Нужен `playwright`.

- `engines_check.mjs` — 54 проверки: каждая страница в WebKit, Chromium и
  Firefox на трёх размерах экрана. Нужны движки:
  `npx playwright install webkit firefox`.
- `touch_check.mjs` — цели под палец и шрифт полей на телефоне, в WebKit.
- `today.test.js` — день по знаку, словарь и слова ко дню: таблицы гочары
  и ведхи из «Пхаладипики», проверка, что правило не самоуничтожается на
  узлах, полнота словаря (каждое слово находится по каждой своей форме, ни
  одна форма не принадлежит двум словам), полнота пожеланий и ровность
  хеша, выбирающего стих дня.
- `glossary_check.mjs` — подсказки к словам в настоящем браузере: мышью,
  пальцем и с клавиатуры, Escape, край экрана, поиск по словарю и переход
  по кириллическому якорю.
- `submit_check.mjs` — нажатие самих кнопок расчёта: форма заполняется как
  человеком (город печатается, подсказка выбирается — и отдельно случай,
  когда в подсказку не ткнули), результат обязан оказаться на экране, а
  кнопка — не сдвинуться ни на пиксель, пока форму заполняют. Появился
  после того, как «Построить карту» на телефоне молча ничего не делала:
  прежние прогоны жали «Показать на примере», а она считает напрямую,
  минуя разбор формы, — и поломка прошла мимо.

Всего 494 проверки в node плюс 112 в настоящих браузерах. Шаги с внешними
зависимостями пропускаются молча, а не роняют прогон.

## Правки, которые понадобятся первыми

- **Названия.** `./tools/rename.sh platform Аруна НовоеИмя`,
  `./tools/rename.sh mentor Дипа НовоеИмя`, `./tools/rename.sh ns Aruna Новый`.
  Три слоя независимы.
- **Цены и состав платного.** `assets/js/core/access.js` — `PACKS`, `PLAN`,
  `FEATURES`. Страница тарифов рисуется из этих же данных.
- **Города.** `assets/js/data/cities.js`, формат `[название, широта, долгота,
  зона IANA, регион]`, долгота восточная положительная.
- **Стихи.** `assets/js/data/verses.js`, поле `themes` связывает стих с небом дня.
- **Темы диалога.** Массив `TOPICS` в `assets/js/ui/dialog-page.js`.
- **Цвета и типографика.** Переменные в `:root` в `assets/css/base.css`.

  системный гротеск — вёрстка не ломается.
- Лагна не считается выше 89,5° широты: там горизонт пересекает эклиптику не
  обычным образом. Форма скажет об этом словами.
- Диапазон дат расчёта — 1800–2200 (форма ограничивает 1900–2100).
- Проверка оплаты клиентская — см. предупреждение выше.

## О названиях и правах

Проект писался с оглядкой на существующий сервис того же жанра. Чтобы не
получить претензий, сделано следующее: все тексты написаны заново, названия
платформы и наставника выбраны свои, внутренняя валюта и сетка цен построены
по другой логике. Подробности и что осталось проверить — в
[docs/IDEAS.md](docs/IDEAS.md), раздел 1.
